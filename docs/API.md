# MetaShop — API Reference

**Public entry point (use this): API Gateway `http://localhost:8080`**

Direct service ports (bypass the gateway; used for service-to-service calls and debugging):
auth-service `http://localhost:8081` · product-service `http://localhost:8082` ·
inventory-service `http://localhost:8083` · cart-service `http://localhost:8084` ·
discovery-server (Eureka) `http://localhost:8761`
Swagger UI: `/swagger-ui/index.html` · OpenAPI JSON: `/v3/api-docs` (per service)

All services use the `/api/v1/...` base path, and the gateway forwards it unchanged. See
`DECISIONS.md` (D-003, D-041).

Responses use the `ApiResponse` envelope for list/collection endpoints:

```json
{ "success": true, "message": "Products fetched successfully", "data": { } }
```

Single-object endpoints (create/update/detail) return the DTO directly.
Errors return `{ "success": false, "message": "...", "data": ... }` with the appropriate HTTP
status (`400`, `404`, `409`, `422`, `500`).

Errors **generated by the gateway itself** (401/403/404/429/503) use the spec §5.3 shape instead:

```json
{ "timestamp": "...", "status": 401, "error": "UNAUTHORIZED", "message": "...",
  "path": "/api/v1/users/me", "traceId": "<correlation id>" }
```

## API Gateway (`:8080`)

Single public entry point. Validates the JWT, propagates identity, applies CORS and rate
limiting, and routes to services through Eureka (`lb://<service-name>`).

### Route table

| Path pattern | Target | Auth |
|---|---|---|
| `/api/v1/auth/**` | `lb://auth-service` | Public |
| `/api/v1/users/**` | `lb://auth-service` | JWT |
| `/api/v1/admin/users/**` | `lb://auth-service` | ADMIN |
| `/api/v1/admin/products/**`, `/admin/categories/**`, `/admin/brands/**` | `lb://product-service` | ADMIN |
| `/api/v1/products/**`, `/categories/**`, `/brands/**` | `lb://product-service` | Public |
| `/api/v1/admin/inventory/**` | `lb://inventory-service` | ADMIN |
| `/api/v1/inventory/**` | `lb://inventory-service` | Public |
| `/api/v1/cart/**` | `lb://cart-service` | JWT |
| `/api/v1/internal/**` | — | **not routed** (404) |

### Headers

| Header | Direction | Meaning |
|---|---|---|
| `Authorization: Bearer <token>` | in | Required on `JWT`/`ADMIN` routes |
| `X-User-Id`, `X-User-Email`, `X-User-Roles` | out | Set from the token claims; **any inbound value is stripped** |
| `X-Correlation-Id` | in/out | Honoured if supplied, otherwise generated; echoed in the response |
| `Retry-After` | out | Seconds to wait, on `429` |

### Behaviour

| Situation | Result |
|---|---|
| Missing / malformed / expired / foreign-signed token | `401 UNAUTHORIZED` |
| Valid token, non-ADMIN role on an ADMIN route | `403 FORBIDDEN` |
| No route matches | `404 ROUTE_NOT_FOUND` |
| Downstream service down or timed out | `503 SERVICE_UNAVAILABLE` |
| More than 5 requests/min per IP on a credential endpoint | `429 RATE_LIMIT_EXCEEDED` |
| Pre-flight from an origin other than the Angular app | `403` |

Credential endpoints rate limited per IP: `/api/v1/auth/login`, `/register`,
`/forgot-password`, `/reset-password`.

### Observability

| Endpoint | Description |
|---|---|
| `GET /actuator/health` | Gateway health |
| `GET /actuator/gateway/routes` | Active route table (read-only) |
| `GET http://localhost:8761/` | Eureka dashboard — shows gateway + all registered services |

## Auth / User Service (`:8081`)

Auth endpoints are public unless marked **JWT**. Errors use the `ApiResponse` envelope
(`success=false, message, data`).

### Auth

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/api/v1/auth/register` | Public | Create a CUSTOMER. Body: `firstName`, `lastName`, `email`, `phone`, `password` → `201` |
| POST | `/api/v1/auth/login` | Public | Body: `email`, `password` → `{accessToken, refreshToken, tokenType, expiresIn, user}` |
| POST | `/api/v1/auth/refresh` | Public | Body: `{refreshToken}` → new pair (rotates the token) |
| POST | `/api/v1/auth/logout` | JWT | Body: `{refreshToken}` → revokes it |
| POST | `/api/v1/auth/forgot-password` | Public | Body: `{email}` → always `200` (never reveals whether the email exists) |
| POST | `/api/v1/auth/reset-password` | Public | Body: `{token, newPassword}` |

**Password policy** (spec 7.4): 8–100 chars with at least one uppercase, one lowercase, one
digit and one special character. Violations → `400` with a `field → message` map under `data`.

**Login response**

```json
{
  "success": true,
  "message": "Login Successful",
  "data": {
    "accessToken": "eyJhbGciOiJIUzM4NCJ9...",
    "refreshToken": "CrRuW9PtPoB--VBIPgbMaut...",
    "tokenType": "Bearer",
    "expiresIn": 900,
    "user": {
      "id": 1, "firstName": "Jay", "lastName": "Pal",
      "email": "jay@example.com", "phone": "+919876543210",
      "enabled": true, "emailVerified": false, "roles": ["CUSTOMER"]
    }
  }
}
```

**Access-token claims**: `sub` (userId), `email`, `roles`, `jti`, `iss`, `iat`, `exp`
(TTL 15 min; refresh token 7 days).

**Security behaviours**
- Email is unique **case-insensitively**; a duplicate → `409`.
- Wrong credentials → `401` `"Invalid email or password"` (never reveals whether the email exists).
- 5 consecutive failures lock the account for 15 min → `423 Locked`.
- A disabled account → `403`.
- Refresh tokens are stored **hashed** and rotated on every use. Reusing an already-revoked
  token revokes **all** of that user's tokens → `401`.
- Changing or resetting the password revokes all refresh tokens.

| PUT | `/api/v1/users/me/addresses/{id}` | Update |

## Inventory Service (`:8083`)

Stock source of truth (spec §9). One counter row per product; reservations move units between
`available` and `reserved`; every change is written to an append-only `stock_movements` trail.

### Public — Availability

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/v1/inventory/{productId}` | Public | `{productId, inStock, availableQuantity}` |

`availableQuantity` is capped at `metashop.inventory.display-quantity-cap` (default `10`), so the
storefront can render "only 3 left" without leaking exact stock levels. Unknown product → `404`.

```json
{ "productId": 50, "inStock": true, "availableQuantity": 3 }
```

### Admin — Stock management

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/api/v1/admin/inventory` | ADMIN | Create the stock row → `201` + `Location` |
| GET | `/api/v1/admin/inventory/{productId}` | ADMIN | Full row incl. `reservedQuantity`, `lowStockThreshold` |
| PUT | `/api/v1/admin/inventory/{productId}` | ADMIN | Set or adjust the quantity |
| GET | `/api/v1/admin/inventory/low-stock` | ADMIN | Products at or below their threshold (paged) |

`POST` body — `lowStockThreshold` is optional (defaults to `5`):

```json
{ "productId": 50, "sku": "SKU-1049", "quantity": 25, "lowStockThreshold": 5 }
```

`PUT` body — supply **exactly one** of `quantity` (absolute) or `adjustment` (signed delta);
`lowStockThreshold` is optional. Supplying both, or neither, is a `400`. An `adjustment` that would
take available stock below zero is a `422`.

```json
{ "adjustment": -3 }
```

Response (`GET`/`PUT`, and the `POST` body):

```json
{
  "productId": 50, "sku": "SKU-1049",
  "availableQuantity": 22, "reservedQuantity": 1,
  "lowStockThreshold": 5, "lowStock": false, "inStock": true,
  "updatedAt": "2026-10-23T11:15:02.894"
}
```

`low-stock` uses the same paged envelope as the product list:
`{content, page, size, totalElements, totalPages, last}`. Add `?threshold=3` to ignore the
per-product thresholds.

### Internal (service-to-service)

> Not routed by the Gateway (404 from the outside). Every call must carry
> `X-Internal-Token: <metashop.internal.token>` — a missing or wrong value is `403`. Responses are
> plain JSON, **not** the `ApiResponse` envelope, so Feign clients stay trivial (D-022).

| Method | Path | Description |
|---|---|---|
| POST | `/api/v1/internal/inventory/reserve` | Hold stock for an order, all-or-nothing |
| POST | `/api/v1/internal/inventory/release` | Return the holds of an order to available stock |
| POST | `/api/v1/internal/inventory/confirm` | Turn the holds of an order into sales |
| POST | `/api/v1/internal/inventory/availability` | Bulk availability check with exact quantities |

`reserve` — duplicate `productId`s are merged; lines are applied in ascending `productId` order:

```json
{ "orderId": 500, "items": [ { "productId": 50, "quantity": 2 } ] }
```

`release` / `confirm`:

```json
{ "orderId": 500 }
```

All three are **idempotent per `orderId`** — a retried call returns the existing reservations rather
than holding or returning stock twice. Response:

```json
{
  "orderId": 500,
  "status": "RESERVED",
  "items": [ { "productId": 50, "quantity": 2, "status": "RESERVED",
               "expiresAt": "2026-10-23T11:15:08.057" } ]
}
```

`status` is the single line status when all lines agree, otherwise `MIXED`.

When **any** line cannot be satisfied the whole reservation is refused with `409` and nothing is
held. `data` lists every offending line:

```json
{
  "success": false,
  "message": "Insufficient stock for 1 item(s)",
  "data": [ { "productId": 50, "requested": 5, "available": 2 } ]
}
```

`availability` — `quantity` is optional per line and defaults to `1`:

```json
{ "items": [ { "productId": 50, "quantity": 3 } ] }
```

```json
{
  "items": [ { "productId": 50, "sku": "SKU-1049", "available": 10,
               "requested": 3, "sufficient": true, "inStock": true } ],
  "allAvailable": true
}
```

Internal callers see the **exact** quantity, unlike the capped public endpoint.

### Reservation lifecycle

| Status | Set when | Counters |
|---|---|---|
| `RESERVED` | `reserve` | `available −n`, `reserved +n` |
| `CONFIRMED` | `confirm` (payment succeeded) | `reserved −n` |
| `RELEASED` | `release` (payment failed / cancelled) | `available +n`, `reserved −n` |
| `EXPIRED` | expiry sweeper (TTL, default 15 min) | `available +n`, `reserved −n` |

`release` on a `CONFIRMED` order, and `confirm` on a `RELEASED`/`EXPIRED` order, are `422`.

### Concurrency

`reserve` uses a single conditional `UPDATE ... WHERE available_quantity >= :quantity`; the loser of
a race updates zero rows and gets `409`. See D-052 and
`src/test/java/com/shopMeta/inventory_service/concurrency/ReservationConcurrencyTest.java`.

## Cart Service (`:8084`)

One cart per user, owned by the JWT subject. The cart stores only `productId` + `quantity` +
the price at add time; **name, image, live price and stock are fetched on every read** from
product-service and inventory-service, so a line can never go stale in the database (spec 10.2).
All endpoints are JWT — there are no guest carts, because the platform has no anonymous identity yet.

### Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/v1/cart` | JWT | The caller's cart with live prices, line totals, subtotal and stock warnings. An empty cart is `200` with empty `items`, never `404`. |
| POST | `/api/v1/cart/items` | JWT | Add a product, or merge into an existing line. Body: `productId`, `quantity` (1..20). Validates product + stock first. |
| PUT | `/api/v1/cart/items/{itemId}` | JWT | Set a line to an absolute quantity (1..20). `itemId` is the line id from the cart response. |
| DELETE | `/api/v1/cart/items/{itemId}` | JWT | Remove one line → returns the updated cart. |
| DELETE | `/api/v1/cart` | JWT | Empty the cart (the cart row is kept, so the next add is cheap). Idempotent. |
| POST | `/api/v1/cart/validate` | JWT | Pre-checkout: is every line active, in stock and within limits? Always `200` — an invalid cart is an answer, not an error. |

### Cart response

```json
{
  "cartId": 3, "userId": 1,
  "items": [ {
    "itemId": 7, "productId": 50, "sku": "SKU-1049", "name": "Keyboard",
    "imageUrl": "/uploads/products/50.png",
    "unitPrice": 99.00, "addedPrice": 89.00, "priceChanged": true,
    "quantity": 2, "lineTotal": 198.00,
    "availableQuantity": 25, "inStock": true, "sufficient": true,
    "productActive": true, "warning": null
  } ],
  "totalItems": 2, "distinctItems": 1, "subtotal": 198.00, "currency": "INR",
  "hasWarnings": false, "warnings": [],
  "updatedAt": "2026-10-23T13:05:00"
}
```

- `unitPrice` / `lineTotal` / `subtotal` are **live** — an estimate of what the cart costs now, not a
  quote. The authoritative amount is the order snapshot.
- `priceChanged` + `addedPrice` let the UI flag "price changed since you added this".
- `warning` explains why a line cannot be ordered right now (inactive, out of stock, "only N left",
  over the quantity limit). Lines are **flagged, not silently dropped**.
- `itemId` (not `productId`) is what `PUT` / `DELETE /items/{id}` use.

### Validation rules

| Situation | Status |
|---|---|
| Unknown `productId` | `404` |
| Product deactivated / deleted in the catalogue | `422` |
| More than 20 units of one product (`metashop.cart.max-quantity-per-item`) | `422` |
| More than 50 distinct products (`metashop.cart.max-distinct-items`) | `422` |
| Not enough stock for the resulting quantity | `409` with `data: {productId, available}` |
| product-service / inventory-service unreachable or breaker open | `503` — the cart refuses rather than render stale prices |
| Another user's `itemId` | `404` (indistinguishable from a missing line — ids are never leaked) |

Mutations validate the product and the stock of the **resulting** quantity before writing, so the
cart can never hold a line that is already impossible to order. The cart only *checks* stock —
**reserving** it is order-service's job at checkout; between two checkouts the same unit can still
be promised to someone else.

### Internal (service-to-service)

| Method | Path | Auth | Description |
|---|---|---|---|
| DELETE | `/api/v1/internal/cart/{userId}` | `X-Internal-Token` | Clear a user's cart after their order was confirmed. Idempotent; plain `204`. |

Not routed by the Gateway (404 from the outside), same as the other internal APIs.

### Concurrency

The unique key on `(cart_id, product_id)` makes a concurrent double-add safe: the losing insert
fails and the caller retries once onto the update path. The `carts` row carries a `@Version`
column, so two racing mutations make the loser fail with a retryable `409` instead of silently
losing a line.

## Status codes

| Code | Meaning |
|---|---|
| 200 | OK |
| 201 | Created (+ `Location`) |
| 204 | No Content |
| 400 | Validation / invalid request (e.g. bad `sort`, both `quantity` and `adjustment`) |
| 401 | Missing / invalid / expired JWT |
| 403 | Authenticated but not allowed (non-ADMIN on `/admin/**`, missing `X-Internal-Token`) |
| 404 | Not found |
| 409 | Conflict — duplicate (SKU / name / slug) or **out of stock** (with the unavailable items) |
| 422 | Business-rule violation (price > MRP, category cycle, releasing a confirmed order) |
| 500 | Unexpected error |
